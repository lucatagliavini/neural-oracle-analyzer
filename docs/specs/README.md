# docs/specs/

Contiene i principi di programmazione e di progetto **stabiliti e vigenti**. Ogni lavoro (codice, refactor, decisioni di design) deve rispettare quanto scritto qui.

## Regole di gestione

- Prima di implementare qualsiasi cosa, leggere tutti i file rilevanti in questa cartella.
- Quando emerge un principio nuovo o duraturo (una convenzione confermata, una regola architetturale, un vincolo di stile), aggiornare o aggiungere il file spec pertinente — non limitarsi ad applicarlo solo nella sessione corrente.
- Un file per argomento (es. `architettura.md`, in futuro eventualmente `convenzioni-bash.md`, `convenzioni-json.md`), non un unico file monolitico.
- Questo è materiale "vivo": a differenza di `docs/sessions/`, non è uno storico — va mantenuto aggiornato e privo di contraddizioni interne.
