### M3 — Tool di log analysis completata

#### Tool prodotti
| Tool | Funzione | Accesso |
|---|---|---|
| `tools/scan_alert_log.sh` | Scansiona alert log Oracle cercando errori ORA-, raggruppa per codice, arricchisce con `data/ora_errors.json` | NFS locale, nessun SSH |
| `tools/tail_alert_log.sh` | Restituisce le ultime N righe dell'alert log come array `{line_number, text}` | NFS locale, nessun SSH |

#### Funzionalità
- `scan_alert_log.sh`: parametri opzionali `--code=ORA-NNNNN` e `--since=YYYY-MM-DD`; output ordinato per count decrescente; campi `{code, description, category, severity, count, first_seen, last_seen, samples[]}` (max 2 sample per codice, troncati a 200 char).
- `tail_alert_log.sh`: parametro opzionale `--lines=N` (default 2000); output `{line_number, text}` con numerazione assoluta nel file originale.
- Entrambi: `log_not_found` JSON se NFS path assente; `invalid_environment` exit 2 come primo controllo; `oracle_version: null` (nessuna connessione DB).
- `data/ora_errors.json`: aggiunto `ORA-00609` (TNS disconnect, categoria `network`, severità `ignorable`) trovato realmente nei log di `axnporadb41`.

#### Scoperte tecniche in M3

1. **JSON escape in awk**: il log Oracle contiene caratteri di controllo (in particolare tab `\t` nei messaggi TNS come `Fatal NI connect error`). Non basta `gsub(/\\/, "\\\\") + gsub(/"/, "\\\"")` — genera JSON invalido. Soluzione: funzione `json_esc()` per-carattere con `sprintf("\\u%04x", code)` per i controlli < 0x20.

2. **Separatore TSV tra le due awk pass**: la prima awk (scanning) passa dati alla seconda (JSON builder) via pipe. Usare `\t` come separatore è sbagliato perché i sample possono contenere tab. Soluzione: separatore `\001` (SOH, non può apparire in log Oracle) con `FS='\001'` nella seconda awk e `sort -t$'\001'`.

3. **Codici ORA- senza zero-padding**: Oracle scrive `ORA-609` nei log (non `ORA-00609`), ma la convenzione del dizionario e dei DBA usa 5 cifre. Necessità di normalizzare a 5 cifre (zero-padded) prima del lookup nel dizionario. Funzione `normalize_code()` aggiunta nella seconda awk.

4. **`match(line, /pattern/, arr)` gawk-only**: la forma a 3 argomenti di `match` è un'estensione gawk. È accettabile perché `scan_alert_log.sh` gira solo su `lxprworkerlana01` (RHEL 9.8, gawk disponibile) — non su target AIX.

5. **`sort -t$'\001' -k2 -rn`**: per ordinare per count decrescente, il sort deve usare lo stesso separatore `\001`. Il `$'...'` ANSI-C quoting funziona correttamente in bash su RHEL.
