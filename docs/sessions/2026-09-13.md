## Fix eseguiti

### R3-01 — Rimossa Strategia B2 da `scan_alert_log.sh`

**Causa radice**: la Strategia B2 (file ridotto per `--code` senza `--since`)
estraeva solo `(riga-1, riga)` per ogni ORA-. Nel log Oracle il timestamp precede
l'errore di **due** righe (riga N=timestamp, N+1=descrizione, N+2=ORA-XXXXX):
estrarre solo `(riga-1, riga)` perdeva il timestamp → `first_seen="unknown"`,
`last_seen=null`, `occurrences_per_day=null`, `full_scan_performed=false` anche
senza filtri.

**Fix**: rimossa B2 completamente. Quando `--code` è presente e count>0, awk legge
il file intero (`AWK_PREFILTER=0`, `full_scan_performed=true`). La B1 (fast-exit
se count=0) rimane e copre il caso peggiore reale (file grande, codice assente).

### R3-02 — `pga_by_pdb_session`: aggiunto MAX_LIMIT=500

Aggiunto `MAX_LIMIT=500` e validazione del tetto in `tools/pga_by_pdb_session.sh`.
Coerente con `top_pga_sessions` (MAX_LIMIT=500) e `tail_alert_log` (MAX_LINES=5000).

### R3-03 — `scan_alert_log`: aggiunto `severity_escalation_thresholds`

Aggiunto campo top-level `severity_escalation_thresholds` all'envelope di successo
di `scan_alert_log`. Dichiara esplicitamente i criteri di escalation di
`severity_effective`:
- `critical`: `occurrences_per_day > 50` OR `count > 500`
- `warning`: `occurrences_per_day > 10` OR `count > 100` (se base non era critical)
- altrimenti: severity di base (o "unclassified")

### R3-04 — `generated_at` normalizzato a UTC in `lib/oracle_conn.sh`

`build_envelope` e `build_error_json` usavano `date -Iseconds` (timezone locale,
es. `+02:00`). Sostituito con `date -u +"%Y-%m-%dT%H:%M:%S+00:00"` → tutti i tool
bash ora emettono UTC. Python (`orchestration.py`) già usava `timezone.utc`.

### R-02 — `resident` in `list_known_instances.sh`: fix via `realpath`

**Causa radice**: il vecchio codice faceva `test -f "$lf"` senza controllare se il
path era un symlink che puntava fuori dall'albero dell'host. In struttura RAC le
istanze guest (es. `NP43CDB0` su `axnporadb41`) hanno il log come symlink verso
l'host proprietario → `test -f` restituiva `true` → `resident=true` su tutte.

**Fix**: dopo `test -f`, si risolve il path reale con `realpath -m` (fallback
`readlink -f`) e si verifica che abbia come prefisso `NFS_HOST_BASE`. Solo allora
`resident=true`.

## Gotcha tecnici emersi

33. **gawk `-f lib` + programma inline incompatibili**: `awk -f libfile.awk '...'` non
    funziona (il programma inline viene ignorato o genera errore). Per usare più file
    `-f` si deve mettere ogni sorgente in un file separato e passare `-f file1 -f file2`.
    Soluzione nei test: `mktemp` + heredoc per il programma secondario.

34. **`realpath -m` vs `readlink -f`**: `realpath -m` accetta path inesistenti (non
    esce con errore), mentre `readlink -f` richiede che il path esista. Per coerenza
    usare `realpath -m` con fallback a `readlink -f` se non disponibile.
