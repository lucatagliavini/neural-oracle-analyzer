### Fix 1 — Supporto Oracle RAC in `lib/oracle_conn.sh`

**Problema**: I tool fallivano con `missing_env_file` su tutte e 4 le istanze RAC. L'env file sul server si chiama `PPBPROD.env` (senza numero) mentre l'istanza si chiama `PPBPROD1`.

**Tentativo 1 (fallito)**: `. ~/PPBPROD1.env 2>/dev/null || . ~/PPBPROD.env`
- Su **ksh** (shell remota), `. file` su file inesistente **termina la shell immediatamente** anche con `2>/dev/null` — il `||` non scatta mai.
- Verificato empiricamente: `SHELL=/usr/bin/ksh`, exit 1 senza output.

**Fix definitivo** in `run_sqlplus_raw()`:
```bash
rac_base=$(printf '%s' "$instance" | sed 's/[0-9]*$//')
# es. PPBPROD1 → PPBPROD, SDC2 → SDC, NP41CDB0 → NP41CDB

if [ "$rac_base" != "$instance" ]; then
    env_loader="f=${HOME}/${instance}.env; [ -f \"$f\" ] && . \"$f\" || . ${HOME}/${rac_base}.env"
else
    env_loader=". ${HOME}/${instance}.env"
fi
```
- `[ -f ~/INST.env ]` verifica l'esistenza **prima** di sourciare — compatibile ksh e bash.
- Il fallback su `BASE.env` scatta solo se `INST.env` non esiste fisicamente.
- Le istanze non-RAC (es. `NP41CDB0`) non sono penalizzate: il primo tentativo riesce e il `||` non viene mai eseguito.

**Gotcha aggiunto** (n. 20 in AGENTS.md): su ksh `. file` su file inesistente termina la shell — usare `[ -f file ] && . file` per gestire l'assenza in modo sicuro.

### Fix 2 — `find` ricorsivo bloccato su NFS RAC in `find_alert_log()`

**Problema**: `get_alert_log_info` e tutti i tool di log si bloccavano indefinitamente su `axprracdb03`. Il tool NFS-only (zero SSH, zero sqlplus) non rispondeva nemmeno entro 10 secondi.

**Diagnosi**:
- `ls /unipol/logs/.../axprracdb03/ppbprod/PPBPROD1/trace/` → istantaneo ✅
- `find /unipol/logs/.../axprracdb03 -name "alert_PPBPROD1.log"` → blocco (timeout) ❌
- `find` entra ricorsivamente nelle centinaia di directory `cdmp_*` nel trace (dump di crash Oracle). Alcune di queste hanno handle NFS problematici → `getdents()` si blocca su quella sottodirectory.

**Fix** in `find_alert_log()` — eliminato `find`, sostituito con glob a profondità fissa:
```bash
# Prima: find "$base" -name "alert_${instance}.log" -path "*/trace/*"
# Dopo:
matches=$(ls -t "${base}"/*/"${instance}"/trace/"alert_${instance}.log" 2>/dev/null)
```
- Sfrutta la struttura NFS nota: `$base/<volume>/<instance>/trace/alert_<instance>.log`
- `ls -t` ordina per data di modifica → il primo risultato è il più recente (gestisce duplicati da migrazione senza `xargs ls -t` aggiuntivo)
- Risposta istantanea anche su host con migliaia di file `.trc` nel trace

**Gotcha aggiunto** (n. 21 in AGENTS.md): `find` ricorsivo su mount NFS può bloccarsi su sottodirectory con handle problematici (tipico su host RAC con directory `cdmp_*`). Usare glob a profondità fissa quando la struttura del path è nota.
