### 2. Limite di concorrenza nel server MCP

**Problema**: chiamate parallele pesanti (es. 4 × `check_memory_pressure` = 12 SSH/sqlplus contemporanei) saturano il server, causando timeout e riavvii del processo uvicorn.

**Soluzione**: semaforo `asyncio.Semaphore` in `mcp/main.py`, configurabile via `MCP_MAX_CONCURRENT` (default: 8).

**Modifiche**:

`mcp/config.py`:
```python
MCP_MAX_CONCURRENT: int = int(os.environ.get("MCP_MAX_CONCURRENT", "8"))
```

`mcp/main.py`:
```python
_call_semaphore: asyncio.Semaphore | None = None

def _get_semaphore() -> asyncio.Semaphore:
    global _call_semaphore
    if _call_semaphore is None:
        _call_semaphore = asyncio.Semaphore(config.MCP_MAX_CONCURRENT)
    return _call_semaphore
```

Nell'endpoint `tools/call`:
```python
sem = _get_semaphore()
async with sem:
    result = await loop.run_in_executor(None, _dispatch_tool, tool_name, arguments)
```

**Comportamento**: con `MCP_MAX_CONCURRENT=8`, il server gestisce fino a 8 chiamate concurrent; le successive vengono accodate nell'event loop asyncio (no rejection, no timeout artificiale — aspettano il loro turno). Le chiamate orchestrate pesanti si autoregolano.
