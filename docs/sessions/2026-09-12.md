## Fix implementati

### B2 — Timestamp identico per tutti i campioni nei tool OS

**Problema**: `os_cpu_stats`, `os_memory_stats`, `os_disk_stats`, `os_network_stats` calcolano
`TS_NOW` una volta prima del loop di campionamento e lo passano come `ts_base` costante all'awk.
Tutti i campioni in `samples[]` hanno lo stesso timestamp, rendendo impossibile correlare
ogni campione al momento effettivo di raccolta.

**Fix**: nei 4 tool OS aggiunto `TS_EPOCH=$(date +%s)` e `-v ts_epoch="$TS_EPOCH"` alle
chiamate awk. Nel blocco `END` dell'awk, per ogni campione `i`:
```awk
ts_i = strftime("%Y-%m-%dT%H:%M:%S+00:00", ts_epoch + (i-1) * interval)
```
Fallback su `ts_base` se `ts_epoch=0` (ambiente senza `date +%s`).

**Dipendenza**: `strftime` in gawk (disponibile su RHEL/MCP) — verificato con test quick.

**File modificati**:
- `tools/os_cpu_stats.sh`
- `tools/os_memory_stats.sh` (due blocchi END: AIX e Linux)
- `tools/os_disk_stats.sh` (campioni io_samples)
- `tools/os_network_stats.sh` (samples per iface)

## Fix aggiuntivo — BUG-04 (ottimizzazione performance `scan_alert_log`)

**Problema**: `scan_alert_log --code=ORA-04030` senza `--since` leggeva l'intero file (58-400 MB) anche quando il codice era assente o rarissimo. Il comportamento era già "trasparente" via `full_scan_performed: true`, ma il costo I/O era identico a un full scan senza filtri.

**Fix — due strategie combinate (Strategia B):**

**B1 — fast-exit** (codice assente): `grep -cE "ORA-0*NNNN"` conta le occorrenze in O(n). Se count=0 → `data: []` senza aprire awk. Costo: una scansione grep sequenziale (~10× più veloce di awk su file NFS).

**B2 — file ridotto** (codice presente): `grep -nE` raccoglie i numeri di riga, poi un awk sequenziale estrae solo `(riga-1, riga)` per ogni hit. Il file ridotto viene passato all'awk principale. Nessun caricamento in memoria del log intero: algoritmo O(n_log) ma con early-stop appena esaurite le righe volute.

**Normalizzazione zero-padding**: il pattern `ORA-0*N` trova sia `ORA-04036` che `ORA-4036` nel log — coerente con la normalizzazione BUG-11 già applicata nell'awk principale.

**`full_scan_performed`**: ora `false` con qualsiasi filtro attivo (`--since`, `--code`, o nessun risultato trovato). `true` solo quando si legge il file intero senza filtri.

**Impatto pratico**: su log da 58 MB, `scan_alert_log --code=ORA-04030` (0 occorrenze) passa da ~3s (full scan NFS) a ~0.3s (grep -c). Con codice raro (es. 5 occorrenze su 1M righe): file ridotto di 10 righe invece di 1M.

**Commit**: `720ce28`

**Test aggiunti**:

- 4 test di regressione su Oracle reale: `full_scan=false` con `--code`, fast-exit con codice assente, Strategia A ancora funzionante
