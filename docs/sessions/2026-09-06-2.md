# Sessione 2026-09-06 (parte 2)

## Cosa è stato fatto

### TOOL-002 — Pre-filtraggio I/O in `scan_alert_log` + proxy HTTP attivo

---

### Analisi del problema

**Sintomo**: `scan_alert_log` su file di alert log grandi (SDC1 PROD, 388 MB) superava il
timeout del client MCP (~30s lato Bob/Claude Code), anche se il tool era funzionante.

**Causa root**: awk leggeva l'intero file da NFS anche quando `--since` era specificato.
Il caso d'uso principale che triggera il problema: "ci sono errori ricorrenti nelle ultime
2 settimane" → Bob genera `--since=YYYY-MM-DD`, ma awk legge comunque tutti i 388 MB.

**Discovery formato timestamp**: il log SDC1 è un file "misto" — le prime ~638 righe sono
in formato testuale Oracle 11g (`Sun May 15 10:00:57 2022`), il resto in ISO 8601
(`2026-09-01T08:16:43.043810+02:00`). Il probe su `head -200` restituiva 0 righe ISO —
ingannante. Soluzione: usare `grep -m1` sull'intero file (si ferma alla prima hit,
istantaneo) per verificare la presenza di almeno una riga ISO.

---

### Fix 1 — Pre-filtraggio I/O in `tools/scan_alert_log.sh`

Blocco aggiunto tra `find_alert_log()` e la chiamata awk:

```bash
if [ -n "$FILTER_SINCE" ]; then
    has_iso=$(grep -m1 -cE "^[0-9]{4}-[0-9]{2}-[0-9]{2}T" "$LOG_PATH" 2>/dev/null || true)
    if [ "${has_iso:-0}" -gt 0 ]; then
        AWK_SINCE_START_LINE=$(grep -n "^${FILTER_SINCE}" "$LOG_PATH" | head -1 | cut -d: -f1)
        if [ -n "$AWK_SINCE_START_LINE" ]; then
            AWK_PREFILTER=1
        else
            # data non trovata nel log → data: [] diretto
            build_envelope ... "[]" ...
            exit 0
        fi
    fi
fi
```

Due branch espliciti `if/else` per la chiamata awk (gotcha bash: `<(cmd)` in variabile
non funziona all'espansione):
- Branch prefilter: `awk ... <(tail -n +"$AWK_SINCE_START_LINE" "$LOG_PATH")`
- Branch normale: `awk ... "$LOG_PATH"`

**4 casi gestiti**:
1. `FILTER_SINCE` non impostato → awk legge file intero (comportamento invariato)
2. ISO + data trovata → awk legge solo la coda rilevante ✅
3. ISO + data non trovata → `data: []` diretto (nessuna scansione inutile) ✅
4. Nessuna riga ISO (log 11g puro) → fallback su file intero (nessuna regressione) ✅

**Risultati**:
| Scenario | Prima | Dopo |
|---|---|---|
| SDC1 PROD 388 MB + `--since=14gg fa` | ~30s (timeout) | **1.4s** ✅ |
| NP41CDB0 56 MB senza `--since` | 1.4s | 1.4s (invariato) ✅ |
| `--since` data futura | ~30s (scansione inutile) | < 0.1s (`data: []`) ✅ |

### Fix 2 — Reverse proxy HTTP attivo su porta 80

Il vhost Apache `:443` aveva `SSLEngine on` con certificati commentati (non attivo).
Il client MCP parlava direttamente con uvicorn su `:8420`.

**Modifica a `etc/httpd/neural-mcp-oracle.conf`**:
- Vhost `:80`: da redirect → HTTPS, ora è il **reverse proxy attivo** con `ProxyTimeout 300`
- Vhost `:443`: commentato intero (placeholder SSL per quando arriverà il certificato)

**Verifica**: `curl -H 'Host: neural-mcp-oracle.servizi.gr-u.it' http://localhost:80/health`
→ `{"status":"ok","service":"neural-oracle-mcp"}` ✅

Quando il certificato SSL sarà disponibile:
1. Ripristinare vhost `:80` come redirect → HTTPS
2. Decommentare vhost `:443` e configurare i path del certificato
