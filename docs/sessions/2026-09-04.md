### Infrastruttura di sistema — vhost Apache + systemd unit

Prima di avviare M7, l'utente ha richiesto di predisporre l'infrastruttura di sistema sul server `lxprworkerlana01`.

**Struttura creata nel repository:**
```
etc/
├── httpd/
│   └── neural-mcp-oracle.conf     → symlink in /etc/httpd/conf.d/
└── systemd/
    └── neural-oracle-mcp.service  → symlink in /etc/systemd/system/
```

- **[`etc/httpd/neural-mcp-oracle.conf`](../../etc/httpd/neural-mcp-oracle.conf)**: VirtualHost Apache per `neural-mcp-oracle.servizi.gr-u.it`. HTTP :80 → redirect 301 HTTPS. HTTPS :443 → reverse proxy verso `127.0.0.1:8420`. Blocco SSL con certificati commentati (da abilitare quando il certificato aziendale sarà disponibile). Log separati in `/var/log/httpd/neural-mcp-oracle-*.log`.
- **[`etc/systemd/neural-oracle-mcp.service`](../../etc/systemd/neural-oracle-mcp.service)**: systemd unit che avvia uvicorn. Legge `MCP_API_KEY` e `MCP_PORT` da `mcp/.env` (non versionato). `Restart=on-failure`.
- **[`deploy.sh`](../../deploy.sh)**: aggiornato per copiare `etc/` via rsync e creare i symlink al primo deploy.

**Gotcha tecnico scoperto**: systemd `EnvironmentFile` espande variabili semplici (`$VAR`) ma **non** la sintassi bash `${VAR:-default}` in `ExecStart`. Corretto usando `$MCP_PORT` direttamente (il default è già nel `.env`).

Il DNS `neural-mcp-oracle.servizi.gr-u.it` era in propagazione al momento della sessione.

### M7 — Server MCP FastAPI — completata

#### Artefatti prodotti

**`mcp/config.py`**
- Carica `.env` con python-dotenv da `mcp/.env`
- Espone: `API_KEY`, `PORT` (default 8420), `TOOLS_DIR` (auto-detect `../tools/`), `TOOL_TIMEOUT` (default 120s)

**`mcp/runner.py`**
- `run_primitive_tool(script_name, *args) → dict`
- Invoca `bash tools/<script_name>.sh` via `subprocess.run` con `capture_output=True`, `timeout=TOOL_TIMEOUT`
- Gestisce: script non trovato → `invalid_argument`, timeout → `query_failed`, output non-JSON → `query_failed`
- In caso di errore subprocess restituisce un envelope sintetico conforme al contratto JSON

**`mcp/main.py`**
- FastAPI app con auth `X-API-Key` header obbligatoria
- Endpoint no-auth: `GET /health`, `GET /tools`
- `POST /mcp` — protocollo MCP wire JSON-RPC 2.0 (Streamable HTTP): `initialize`, `tools/list`, `tools/call`
- 13 endpoint `POST /tools/{tool_name}` — wrap 1:1 REST per debug diretto
- `_dispatch_tool()` — traduce `tools/call` MCP negli argomenti dei primitivi bash
- `MCP_TOOLS` — catalogo con `inputSchema` JSON Schema completo per tutti i 13 tool
- Parametri opzionali mappati per tool con filtri (`scan_alert_log`, `tail_alert_log`, `top_pga_sessions`)

**`~/.bob/settings/mcp.json`** (globale Bob)
- URL: `http://lxprworkerlana01.servizi.gr-u.it:8420/mcp`
- Header: `X-API-Key` con chiave dal `.env` del server

**Gotcha protocollo MCP**: Bob si aspetta JSON-RPC 2.0 su `POST /mcp`, non endpoint REST custom. Il server REST precedente causava "failed to initialize after 3 attempts". Aggiunto il layer MCP wire mantenendo gli endpoint REST per debug.

**Gotcha uvicorn bind**: uvicorn era in ascolto su `127.0.0.1` (loopback only) — non raggiungibile da WSL. Corretto con `--host 0.0.0.0`.

### Tool NFS e orchestrati aggiunti nella stessa sessione

Dopo M7, nella stessa sessione (riapertura chat), sono stati aggiunti 4 nuovi tool e migliorati i catalogo MCP:

**Nuovi tool bash (lettura NFS locale, zero SSH, zero sqlplus):**
- [`tools/list_known_instances.sh`](../../tools/list_known_instances.sh) — istanze configurate per host da NFS, funziona anche se host è down
- [`tools/get_alert_log_info.sh`](../../tools/get_alert_log_info.sh) — metadati alert log (path, size_bytes, age_hours) senza aprirlo
- [`tools/list_all_hosts_and_instances.sh`](../../tools/list_all_hosts_and_instances.sh) — inventario completo host+istanze in una chiamata

**Nuovo tool orchestrato Python:**
- `list_all_instances_status` in [`mcp/main.py`](../../mcp/main.py) — chiama `identify_instance` su tutte le istanze di un host in parallelo (`ThreadPoolExecutor`), restituisce stato operativo per ciascuna

**Gotcha tecnico**: `list_all_hosts_and_instances.sh` aveva un bug awk — l'uso di `SUBSEP` come chiave composita per host+istanza generava righe duplicate (37 invece di 8). Corretto usando chiave stringa `host ":" inst` e array `inst_name[host, idx]`.

**Descrizioni MCP aggiornate**: tutte le descrizioni di `TOOL_CATALOG` e `MCP_TOOLS` riscritte con tag di categoria (`INVENTARIO`, `STATO OPERATIVO`, `ANALISI LOG`, ecc.) e cross-reference espliciti per guidare Claude nella scelta del tool giusto. Contesto: un DBA aveva chiesto "quali istanze ci sono su axnporadb41?" e il sistema aveva risposto con l'inventario invece dello stato operativo.

**Infrastruttura NFS scoperta:**
- noprod: 8 host (`axnporadb41–44`, `axnporadb51–54`)
- prod: 10 host (`axproradb41–44`, `axproradb51–54`, `axprracdb03–04`)
