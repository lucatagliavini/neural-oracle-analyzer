## Feature implementate

### C3 — `--until=YYYY-MM-DD` su `scan_alert_log`

**File**: `tools/scan_alert_log.sh`, `mcp/main.py`, `mcp/orchestration.py`

Aggiunto il parametro `--until` a `scan_alert_log` per delimitare la finestra
temporale **superiore**. Finora esisteva solo `--since`; senza `--until` era
impossibile isolare un incidente passato senza fare due scansioni e una sottrazione
manuale (problema identificato come B1 in BACKLOG).

**Uso tipico**: `since='2026-07-21', until='2026-07-21'` per vedere **solo** gli
errori del 21 luglio senza contaminazione degli episodi successivi.

**Dettagli tecnici**:
- Validazione formato `YYYY-MM-DD` (come `--since`)
- Validazione coerenza: `since > until` → `invalid_argument`
- Filtro awk: `last_ts > filter_until "T99"` (confronto lessicografico ISO 8601)
- Campo `filter_until` aggiunto all'envelope top-level per trasparenza
- `runbook_ora04030` in `orchestration.py` accetta `until` e lo passa alle 3 scan
- `inputSchema` MCP aggiornato (sia nella tool list che nei REST model)
- `ScanAlertLogRequest` (Pydantic) aggiornato con campo `until`
- `RunbookOra04030Request` aggiornato con campo `until`

### C2 — `include_raw: bool` sui runbook compositi

**File**: `mcp/orchestration.py`, `mcp/main.py`

Aggiunto parametro `include_raw` (default `True`) a tutti e 4 i runbook compositi:
- `diagnose_instance`
- `check_memory_pressure`
- `runbook_ora04030`
- `diagnose_os_pressure`

Quando `include_raw=False`: `data=[]` invece dei raw results. Il `summary` è sempre
presente e completo. Questo risolve definitivamente BUG-01 per i casi in cui il
chiamante voglia solo il verdetto interpretativo senza il payload grezzo.

**Riduzione payload**:

| Tool | `include_raw=true` | `include_raw=false` |
|---|---|---|
| `check_memory_pressure` | ~200 KB | ~2 KB |
| `diagnose_os_pressure` | ~260 KB | ~5 KB |
| `runbook_ora04030` | ~500 KB | ~5 KB |
| `diagnose_instance` | ~50 KB | ~5 KB |

**Dettagli tecnici**:
- `data = [...] if include_raw else []` — minima modifica, nessun side effect
- Tutte le firme Python con `include_raw: bool = True` (backward compatible)
- REST endpoint aggiornati: `_RunbookBaseRequest`, `RunbookOra04030Request`,
  `DiagnoseOsPressureRequest` estendono `_IncludeRawMixin(include_raw: bool = True)`
- `inputSchema` MCP aggiornato per tutti e 4 i tool
- Il dispatch JSON-RPC usa `bool(args.get("include_raw", True))` per la conversione
  sicura dall'input MCP (che può essere `None`)
